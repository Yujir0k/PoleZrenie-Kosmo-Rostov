# NDVI v8 — версия с RMSE 0.0712

Этот архив предназначен для передачи разработчику или другому Codex-агенту,
который будет встраивать интерполяцию NDVI в продукт.

## Что отправлять на платформу

Отправлять нужно только файл `submission.csv` из корня архива.

- подтверждённый результат на replacement test: **RMSE 0.0712**;
- SHA-256 файла: `BE4F94BECFCED157665E345C4FF811868185CA702ADA61EF701AA76ACD0D618A`;
- строк: `2323`;
- заголовок: `anon_polygon_id,date,primary_ndvi_true`.

Не отправляйте ZIP, `New_test.csv` или более позднюю v9: увеличение числа
итераций ухудшило leaderboard, поэтому финальной остаётся v8.

## Быстрая проверка готового submission

```powershell
python validate_submission.py --test data/New_test.csv --submission submission.csv --expected-sha256 BE4F94BECFCED157665E345C4FF811868185CA702ADA61EF701AA76ACD0D618A
```

Скрипт проверяет заголовок, число и порядок ключей, формат дат, дубли, NaN,
бесконечности и контрольную сумму.

Контрольный повторный запуск из этого handoff-пакета воспроизвёл исходный CSV
бит-в-бит: максимальное и среднее абсолютное расхождение равны `0.0`, SHA-256
совпал.

## Как воспроизвести прогноз

Рекомендуется Python 3.11–3.13, 64-bit. GPU не требуется.

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python run_v8.py
```

Новый файл появится в `output/submission.csv`. Первый запуск строит признаки и
обучает модели, поэтому на CPU занимает несколько минут. Промежуточные признаки
сохраняются в `work/features` и повторно используются.

Проверка воспроизведённого файла:

```powershell
python validate_submission.py --test data/New_test.csv --submission output/submission.csv
```

## Входные данные

- `data/train_dataset.zip` — исходный train организаторов;
- `data/New_test.csv` — replacement test, на котором получено 0.0712;
- `data/old_private_features.csv` — снятый с проверки предыдущий test;
- `data/old_ground_truth.zip` — опубликованная организаторами разметка старого test.

Старая разметка используется только для восстановления исторического контекста.
Значение текущей скрытой точки не попадает в её признаки.

## Архитектура v8

1. Для каждого `is_synthetic_gap=True` строятся mask-safe признаки соседних дат,
   сезонности, погоды и других полигонов.
2. Опубликованная разметка старого test восстанавливает донорские временные ряды:
   19 historical-полей и сезон 2025 для текущих идентификаторов.
3. Prior — ансамбль CatBoost и двух LightGBM.
4. Три LightGBM-expert предсказывают значение отдельно для Sentinel-2, Landsat и
   MODIS; CatBoost-классификатор оценивает вероятный источник скрытой съёмки.
5. Финальный прогноз фиксирован как `0.20 * prior + 0.80 * source_gated`.

В v8 нет BiGRU, rank-2 factor и последующего калибровочного blend: эти компоненты
не дали достаточного честного прироста в replacement-режиме.

## Интеграция в продукт

Точка входа batch-инференса — `run_v8.py`. Для серверной интеграции передавайте
пути аргументами; полный список доступен через `python run_v8.py --help`.

Модель обучается при batch-запуске, а не загружает один сохранённый бинарный вес.
Для продукта разумно запускать её как фоновую задачу и кэшировать каталог `work`.
Выход содержит прогнозы только для строк `is_synthetic_gap=True`.

## Формат submission и расхождение в документах

В старом PDF указан столбец `primary_ndvi_pred`. Фактический валидатор выбранной
задачи требует `primary_ndvi_true`: ошибка платформы прямо сообщала об отсутствии
этого столбца, а файл v8 с `primary_ndvi_true` был принят и получил 0.0712.
Поэтому менять заголовок в `submission.csv` нельзя.

## Что покрывает пакет по критериям

- метрика: 0.0712, что соответствует 8.64 балла из 30 по формуле GapScore;
- batch-инференс: отдельная воспроизводимая команда;
- документация: зависимости, входы, выход и архитектура описаны;
- исследование: журнал экспериментов лежит в `docs/EXPERIMENTS.md`;
- воспроизводимость: версии библиотек и SHA-256 артефактов зафиксированы.

Веб-сервис, карта, автоматический сбор данных и детекция аномалий находятся вне
этого handoff-пакета. Их нужно подключить в основном продуктовом репозитории — это
отдельные критерии хакатона и данный ZIP их не закрывает.
